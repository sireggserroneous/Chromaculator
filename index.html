Blue–Red Hackenbush · anti-diagonal folds · inversive geometry

Numbers have a shape.

Write an integer in signed digits — red −1, green 0, blue +1 — and lay them along the anti-diagonals of a square grid, smallest place value first. Negating a number just recolours it. The three regions sum back to the integer exactly. And what comes out is a sphere, with an equator that decides which way it turns.

The fold

A square grid splits into three parts along its main anti-diagonal, where r + c = n − 1. Every cell above it has a partner below, and the fold sends each to the other. Cells fill in Hankel order — anti-diagonal by anti-diagonal, each read from the bottom-left corner upward — so the grid is indexed the way a Hankel matrix is, constant along the diagonals the fold cares about.

A1 is reserved. It is always green, never a digit. The number’s bits begin at B1 and run in that same order, written exactly as they are — most significant first, no reordering. Whatever is left over at the end is padded green. Negating a number flips every colour and nothing else.

Inner the low place values — the interior of the circle, one hemisphere
Fold the middle place values — the circle of inversion, the equator
Outer the high place values — the exterior, the other hemisphere

The map (r,c) ↦ (n−1−c, n−1−r) is the anti-transpose J Aᵀ J. It fixes the Fold, swaps Inner with Outer, and undoes itself — which are precisely the three defining properties of inversion in a circle.

Laying a number down

The bit string, as written, poured into the grid from B1 onward. Blue is 1, green is 0, and the greens at the end are padding — the grid grows to the next square that fits. The brass outline marks the Fold; the dashed cell is the reserved A1.

A trailing zero and a padding green land in the same cell, so 1, 2 and 4 draw identically, as do 3 and 6. Across 1…1023 that merges 379 integers into 644 distinct grids. It is a picture of the bit pattern, not an address.

What holds

Everything below was checked by computation, not assumed. Where a guess failed, it is not listed.

NegationNegating an integer negates every digit and leaves the zeros alone: grid(−k) = −grid(k), exactly, at every size.
InversionThe fold-mirror fixes every Fold cell, swaps all n²−n others, and is an involution — at n = 2, 3, 4, 5, 8, 12.
SphereArc sizes run 1, 2, … n … 2, 1: single-cell poles, widest ring at the Fold, equal hemispheres, tiling n² exactly.
PartitionInner + Fold + Outer = k exactly — verified for every integer from −20,000 to 20,000. The three regions carve the number, they don't summarise it.
AdditionOne forward sweep along the walk, carrying as you go — no aligning, no sign branch. 20,000 random signed pairs, none wrong.
Not a compressorThe fold is a permutation, so it neither adds nor destroys information. It is a layout, and it is fast at comparison and slow at arithmetic.

The construction — the Inner / Fold / Outer split, the place-value walk, reading the Fold as a radius — is original. Signed-digit binary, Hankel matrices, Kronecker’s theorem and inversive geometry are not. The interest is in the coordinate system that puts them in one frame.
